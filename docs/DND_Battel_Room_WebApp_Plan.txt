
  # DND Battle Room Web App

  ## Summary

  Build a greenfield web app for online DND sessions where a room creator acts as DM, shares a room link, edits the battle map, manages
  NPC/monster tokens, and players join with a nickname to control their own character tokens.

  Use Next.js + React + TypeScript for the app, Supabase Postgres + Realtime/Presence for multiplayer state, and react-konva/Konva for the
  draggable battle map canvas. This fits the need for online rooms, live token movement, user presence, and dice results without building
  a custom WebSocket server. Sources: Next.js docs (https://nextjs.org/docs), Supabase Realtime docs
  (https://supabase.com/docs/guides/realtime), Konva React drag docs (https://konvajs.org/docs/react/Drag_And_Drop.html).

  ## Key Changes

  - Create a Next.js app with routes for:
      - / room creation/join screen.
      - /room/[roomCode] live game table.
  - Add guest identity:
      - User enters nickname and chooses a color.
      - App stores a generated guest ID in localStorage.
      - No email/password in v1.
  - Add room roles:
      - First user who creates the room is dm.
      - Joining users are player.
      - DM can edit map settings, create/edit/delete any token, and move any token.
      - Players can create and move only their assigned character token unless DM grants control.
  - Add battle map:
      - Custom square grid with configurable rows, columns, cell size, background color, and optional background image.
      - Pan/zoom support.
      - Snap-to-grid token movement.
      - Simple drawing layer for lines, walls, and markers.
  - Add tokens/chips:
      - Token name, icon, owner, size, position, color ring, visibility, and type: character, npc, monster, object.
      - Icons can be emoji or uploaded image in v1.
      - Colored outer ring shows who owns or controls the token.
  - Add top player bar:
      - Shows every connected user with nickname, color, role, and online status.
      - Under each profile, show their latest public dice result.
  - Add dice roller:
      - Buttons for d4, d6, d8, d10, d12, d20, d100.
      - Support expressions like 2d6+3.
      - Public rolls appear to everyone.
      - Private rolls are stored but only visible to the roller; if a player rolls privately, the DM can also see it.
  - Add useful v1 extras:
      - Turn tracker / initiative list.
      - Token health/status notes visible to DM.
      - Room invite link copy button.
      - Basic chat/event log for token moves, dice rolls, and joins.

  ## Data And Realtime

  - Store rooms, room members, maps, tokens, dice rolls, drawings, and initiative entries in Supabase Postgres.
  - Use Supabase Realtime database changes for shared room state.
  - Use Supabase Presence for online user list.
  - Use row-level security so guests can only read/write data for rooms they joined, with stricter rules for DM-only edits.
  - Keep map/token updates lightweight: persist final token position after drag, and optionally broadcast temporary drag previews without
    saving every mouse movement.

  ## Test Plan

  - Unit test dice parsing: valid expressions, invalid expressions, modifiers, multiple dice, private/public roll flags.
  - Permission tests:
      - DM can edit map and all tokens.
      - Player can only edit own token.
      - Private rolls are hidden from unauthorized users.
  - UI tests:
      - Create room, join as second player, create token, move token, roll dice.
      - Verify player bar updates when users join/leave.
      - Verify grid settings change the visible board correctly.
      - Player joins by link.
      - Token movement syncs.
      - Dice results appear under profiles.
      - Private DM roll stays hidden from player.

  ## Assumptions

  - Version 1 uses square grids, not hex grids.
  - No email accounts in v1; guest nickname identity is enough.
  - Uploaded token/map images are stored in Supabase Storage.
  - Deployment target is Vercel for the Next.js app and Supabase for backend services.
  - The first implementation should prioritize a working online tabletop over advanced features like fog of war, character sheets, spell
    automation, or full campaign management.

  ## Current Fix Plan: Proxy Navigation, UI, Browser QA, And End Report

  The current app needs another implementation pass because room creation is not reliable in the preview proxy URL and the UI is still too
  unclear for normal use.

  Planned changes before coding:

  - Fix proxy-safe navigation:
      - Room creation must work from preview URLs like /proxy/3000/.
      - Avoid absolute client navigation that escapes the preview proxy.

  - Improve the lobby UI:
      - Make the first screen a clear room lobby instead of a hidden create/join form.
      - Show separate Create Room and Join Room panels.
      - Keep nickname and color selection visible and easy to understand.
  - Improve the room UI:
      - Add clearer toolbar/status areas for room code, role, invite, and sync state.
      - Add empty states where controls otherwise look broken.
      - Keep map, token, dice, initiative, and log controls visually separated.
  - Add browser interaction testing:
      - Install Playwright tooling.
      - Add tests that click Create Room, verify the room page loads, add a token, and roll dice.
      - Use browser screenshots/inspection to confirm the UI is visible and interactive.
  - Add an end report:
      - Record what was broken, what changed, which checks passed, browser verification notes, and remaining limitations.

  Acceptance criteria:

  - The home page visibly contains a Create Room button.
  - Clicking Create Room from the normal or proxied app URL opens a room page.
  - The room page shows a usable tabletop UI, not only a blank/loading state.
  - Token creation and dice rolling visibly update the room.
  - npm run lint, npm run build, npm audit, and Playwright checks pass or are documented with concrete blockers.

  The prototype screens are not enough for the intended DND tabletop product. The next implementation pass must rebuild the app UI around
  the tabletop workflow, add a real Supabase-backed sync path, and verify the website through Playwright screenshots and browser flows.

  Implementation requirements:

  - Rebuild the lobby as an app dashboard:
      - Use clear room creation and room joining sections.
      - Keep profile setup compact but visible.
      - Make room codes, recent rooms, and connection state obvious.
      - Keep navigation safe for normal localhost and proxied preview URLs.
  - Rebuild the tabletop as the primary product screen:
      - Make the battle map the central surface.
      - Add a top command bar for room code, invite, role, online players, and sync state.
      - Keep dice, tokens, initiative, log, and DM map controls in structured tool panels.
      - Add empty, loading, and error states that explain what is happening.

  - Add Supabase as the production sync path:
      - Add a Supabase client that activates when NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY are configured.

  - Strengthen browser verification:
      - Add Playwright flows for create, join, add/edit/move token, roll dice, and proxy-path navigation.
